Versioning & Anchoring Standard Release Registry

Current v0.1.0 Scope: deterministic commitment + release manifests Anchoring infrastructure: not included in v0.1.0

This registry records releases of the Versioning & Anchoring Standard itself. It is not an application registry, scoring system, evidence service, prediction registry, identity layer, or commercial product. Its purpose is to point to the standard’s release manifest, manifest hash, and timestamp receipt so a release can be independently verified.

Release registry

Each row identifies a frozen standard release and the files needed to verify it. Later documentation or site cleanup commits do not rewrite previous releases.

What this release record means

  • manifest.json is the canonical release record.
  • manifest.sha256 is the SHA-256 hash of the canonical manifest bytes.
  • manifest.sha256.ots is the timestamp receipt for the published hash file.
  • The release is append-only: if the standard changes, publish a new version instead of rewriting this one.

What this page is not

  • Not a blockchain anchoring specification.

Verification model

Verification depends on the original release content plus the published hash record. A hash is one-way: it cannot recreate the original. It can only confirm that a supplied file matches the published digest. 

1) Obtain the release manifest:
   ../releases/v0.1.0/manifest.json

2) Canonicalize the manifest using the v0.1.0 rules:
   - recursive lexicographic key sorting for objects
   - arrays preserve order
   - JSON.stringify(..., null, 2)-style formatting
   - UTF-8 bytes
   - no trailing newline

3) Compute:
   SHA-256( UTF-8(canonicalJson(manifest)) )

4) Compare the result with:
   ../releases/v0.1.0/manifest.sha256

5) If using the timestamp receipt, verify:
   ../anchors/v0.1.0/manifest.sha256.ots

Scope boundary

This registry is intentionally narrow. It records releases of the base standard only. Profiles and applications can be built on top of the standard, but their rules, identities, scoring systems, user interfaces, governance models, and anchoring mechanisms are outside the scope of v0.1.0.
